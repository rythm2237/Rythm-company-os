# Software Company Template v1.0

`ready_software_company_v1` is a reusable RYTHM Company OS operating system for governed software product delivery. It uses the existing tenant, Agent Studio, project, milestone, meeting, decision, action, approval, knowledge, routing, Integration Gateway, CRM, communication, finance and calendar foundations.

## Organization contract

- 7 departments: Executive & Operations, Product, Design, Engineering, Quality & Security, Growth & Customer, and Finance & Legal.
- 19 reusable professional Agent templates. Full-company provisioning requires a `company_studio` entitlement with capacity for the roster; each Agent can also be provisioned individually when Agent creation is enabled.
- Every provisioned Agent starts paused with external actions disabled, tenant company knowledge connected, an active professional foundation, all declared specializations, adaptive routing policy, and an internal RYTHM Master-level verification. This is not an academic degree or professional license.
- The template records zero included monthly company cost and no separate sale price. It does not invent commercial pricing.

## Delivery workflow

The 17-stage `software_product_delivery_v1` workflow moves from Idea and Discovery through Requirements, Architecture, Design, Implementation, independent QA and Security Review, Preview, Acceptance, Production Approval, Deploy, Monitor, Support and Iterate.

Milestones are created as planned records. A stage is not complete until its declared evidence exists. The first project action is `Capture the founder/customer product brief.`; no customer requirement, product fact or completion status is fabricated.

## Governance and integrations

- Human CEO authority is preserved for material scope/cost decisions, protected-branch merges, production deployment, production migrations, DNS writes, refunds and governed external communication.
- Restricted destructive capabilities remain `human_only` and are not included in recommended Agent grants.
- Integration profiles contain capability and scope recommendations only. They are applied only after the customer connects a tenant-owned integration; credentials remain in Supabase Vault and are never copied into a template, prompt or public table.
- Organization setup dependencies expose GitHub, Vercel and Supabase as recommended, with Cloudflare, Stripe, Google Workspace and Microsoft 365 available when the product needs them.

## Validation

Run `npm run test:software-company` to verify the roster, departments, reporting contract, workflow stages, professional specializations, RLS coverage, approval gates, credential non-copy invariant and first project action. CI runs this contract test before the production build.
